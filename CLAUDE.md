# Slotik — рабочие соглашения для Claude

## Workflow

- **Все изменения делать прямо в `master`**, не создавать отдельные ветки и не использовать worktree (`.claude/worktrees/`). Если оказался в worktree — перемещай результат в основной репозиторий и работай там.
- Файлы памяти/контекста хранить **только внутри репозитория** (например, в `docs/`), не писать в `~/.claude/memory/`.

## Состояние продукта

- Ключевой сценарий: холодный пользователь регистрируется → онбординг из трёх
  экранов → готовая ссылка → его клиент выбирает свободный слот и бронирует.
  Разбор переделки — [docs/product-rework.md](docs/product-rework.md),
  предшествующее ревью — [docs/product-review.md](docs/product-review.md).
- Владелец веб-аккаунта живёт под `owner_chat_id = web:<id>`. Заведения ищутся
  по этому полю; при привязке Telegram они переносятся на chat_id мессенджера.
  Ломать эту связь нельзя — именно из-за неё активация была нулевой.
- Свободное время считается на лету: смена минус брони, нарезка по
  `slot_duration_minutes` (`backend/src/services/free-slots.ts`). Слот в БД —
  это рабочее окно, а не бронируемый интервал.
- `slot_duration_minutes = 1440` («сутки») — отдельная семантика: день
  бронируется целиком, часы работы означают заезд/выезд. Нарезки нет.
- Границы свободных интервалов отдаются клиенту в абсолютных минутах
  (`startMinutes`/`endMinutes`, за полночь больше 1440). Не считать переход
  через полночь второй раз на фронте — там это уже приводило к багу.
- Расписание перепубликуется через `clearAvailableSlots`, не через `clearDay`:
  `clearDay` стирает и брони клиентов.
- Уведомления и сброс пароля для веб-владельцев идут по SMTP (`SMTP_*` в env).
  Без переменных сервис работает, но письма не уходят.
- Скриншоты лендинга снимаются с живого приложения — см.
  [landing/media/README.md](landing/media/README.md). Рисовать их руками нельзя:
  один раз это уже привело к тому, что лендинг обещал не то, что делает продукт.

## Стратегический контекст

- Текущая ниша «бани/глемпинги» рассматривается как структурно слабая (см. [docs/monetization-ideas.md](docs/monetization-ideas.md)).
- Приоритетный шаг — расширение ICP до «арендуемых пространств по слотам» (корты, escape rooms, прокат, бильярдные).
- Вторая опция — самозанятые мастера beauty/wellness, конкурент DIKIDI, обязателен free-tier.
- Монетизация выстраивается вокруг комиссии с предоплат (главный источник), freemium-апсейлов по фичам и SMS-наценки, а не подписки одиночек.
