# Бот учёта квитанций

@bratbuhbot работает отдельным Docker-контейнером на сервере «Германия-4» и получает сообщения напрямую через Telegram Bot API. Основной бот бронирований использует другой токен и другую базу.

## Деплой

На «Германии-4» код лежит в `/opt/reservation-service/receipt-bot`, настройки с токеном — в `receipt-bot/.env`, база — в `data/receipt-bot/receipts.sqlite3` относительно `/opt/reservation-service`.

GitHub Actions запускает **Deploy receipt bot** после изменений в `receipt-bot/` на `master`. Для ручного редеплоя запустите тот же workflow на `master`. Он тестирует код, проверяет SSH-ключ и имя хоста Германии-4, создаёт копию SQLite, запускает контейнер и сверяет SHA запущенного коммита.

```sh
cd /opt/reservation-service
docker compose -f receipt-bot/compose.yaml ps
docker compose -f receipt-bot/compose.yaml logs --tail=20 bot
```

На этом Mac не должен одновременно работать второй экземпляр @bratbuhbot: два процесса с одним токеном мешают друг другу получать сообщения.

Журнал бота доступен через `docker compose logs` на «Германии-4». Бот записывает `update_id`, ID чата и сообщения, тип вложения и его размер. Для пропущенного текста видна причина (например, неверный формат платежа или выключенный учёт группы); для изображения — этап обработки и причины отказа каждой попытки OCR. Успешная запись и дубликат тоже отмечаются. Строки одного сообщения можно найти по `update_id`. Текст переписки, OCR-текст, имена, суммы и номера квитанций в журнал не записываются.

Получение сообщений и ответы проверьте командой `/ping` или `/status` в личном чате с @bratbuhbot. Эти команды не раскрывают данные группы. `/start` в личном чате тоже отвечает, даже если личный учёт не настроен.

Бот проверяет соединение с Telegram раз в минуту. После трёх неудачных проверок он завершает процесс, и Docker запускает его заново.

Локальный запуск из каталога `receipt-bot`: скопируйте `.env.example` в `.env`, укажите `BOT_TOKEN`, установите Python 3.10+, Tesseract с `rus` и `eng`, затем выполните `pip install -r requirements.txt` и `python bot.py`. Тесты: `python -m unittest discover -s tests -q`.

## Подключение группы

Добавьте @bratbuhbot в группу и включите учёт командой `/enable` от любого участника. В BotFather у бота должен быть выключен Privacy Mode, иначе обычные фотографии и текстовые сообщения группы не поступят. `/chatid` покажет ID группы. После новой квитанции или сообщения вида `Оплатил 800 ₽` либо `Имя: 800 ₽` бот сразу запишет платёж и напишет «Денег в казне: …». Кнопка «Отменить» удалит ошибочную запись. `/balance` показывает текущую казну и сумму за всё время. `/month` и `/month YYYY-MM` показывают сумму за месяц, сумму за всё время и текущую казну. Отчёт за месяц приходит первого числа после 00:05 по `Asia/Tomsk`. `/reset` доступна администраторам группы: казна станет нулевой, а платежи, прежние отчёты и запись об обнулении сохранятся в SQLite. Платежи с датой до последнего обнуления в текущую казну не входят даже при позднем импорте.

Для небольшого чека внутри скриншота переписки бот повторно распознаёт светлую область документа в большем масштабе. Неоднозначные дата, сумма или номер операции по-прежнему отклоняются. Команда `/status` и отдельное сообщение «статус» показывают, что бот на связи, включён ли учёт группы, и текущую казну. В группе обычный текст доходит до бота только при выключенном Privacy Mode; команда `/status` доступна и с ним.

Если спросить бота в группе «Брат бухгалтер, за весь период считает?» или упомянуть `@bratbuhbot` с вопросом о балансе, он покажет текущую казну и сумму за всё время. Обычные разговорные сообщения он не считает платежами.

`/info` показывает все команды, форматы сообщений и правила учёта. `/start` и `/help` открывают ту же справку. Список команд также публикуется в меню Telegram при запуске бота.

## Старая история группы

Telegram Bot API не выдаёт боту сообщения, отправленные до его добавления. Для группы **«БРАТЬЯ СВЕТОВЫ»** выгрузите историю через Telegram Desktop: меню группы → **Export chat history**, формат **JSON**, включите **Photos**, выберите весь нужный период. Сохраните экспорт локально: `result.json` и папку с фотографиями. Не загружайте экспорт с перепиской и чеками в GitHub.

После добавления бота в группу и команды `/enable` получите её ID через `/chatid`. В каталоге `receipt-bot` выполните предварительную проверку:

```sh
python import_history.py '/путь/к/экспорту' --chat-id -1001234567890
```

Скрипт покажет количество найденных платежей, сумму до исключения дублей и ошибки OCR, не меняя базу. Сверьте сомнительные квитанции и затем добавьте `--apply` для записи. Локальная проверка не изменяет серверную базу. Для импорта на сервер скопируйте каталог экспорта в `data/receipt-bot/import/` и запустите из корня `reservation-service`:

```sh
docker compose -f receipt-bot/compose.yaml exec -T bot python import_history.py /app/data/import --chat-id -1001234567890
docker compose -f receipt-bot/compose.yaml exec -T bot python import_history.py /app/data/import --chat-id -1001234567890 --apply
```

Повторный импорт пропускает дубли по номеру квитанции или ID текстового сообщения. После импорта `/balance` покажет итог всей группы; `/month YYYY-MM` разнесёт платежи по дате квитанции или сообщения.

Импорт учитывает только распознанные банковские квитанции и строгие текстовые формы платежа. Обычные фотографии и разговоры не добавляются. Ошибки нужно проверить вручную: число найденных платежей не означает, что каждый перевод из переписки подтверждён.

Для нескольких проверенных вручную платежей можно отправить в уже включённую группу одну команду `/backfill` с отдельной строкой на каждый платёж: `2026-11-08 15:44:34 | Екатерина Фефилова | 800 | receipt:1-112-468-530-079`. Для платежа без номера используйте `manual:уникальный_ключ`. Повтор команды пропустит уже записанные ключи. Номер квитанции следует сверить со скриншотом до загрузки.
