# Бот учёта квитанций

Бот работает отдельным контейнером внутри `reservation-service`. Домен и reverse-proxy ему не нужны: он получает новые сообщения опросом Telegram. Основной бот бронирований использует другой токен и другую базу.

## Деплой

Workflow `.github/workflows/deploy-receipt-bot.yml` автоматически запускается при изменениях в `receipt-bot/` на ветке `master`; его также можно запустить вручную в GitHub Actions. Он проверяет тесты, копирует только папку бота на сервер, делает резервную копию SQLite и пересобирает контейнер. Для запуска нужен отдельный секрет GitHub `RECEIPT_BOT_TOKEN` — токен **@svetovtestbot**, а не токен бота бронирований. Если секрета нет, деплой завершится ошибкой. База квитанций хранится отдельно в `data/receipt-bot/receipts.sqlite3`; каталог `data` не участвует в синхронизации.

На этом Mac уже может работать локальный экземпляр @svetovtestbot. Перед включением серверного контейнера остановите его: два процесса с одним токеном мешают друг другу получать сообщения.

Локальный запуск из каталога `receipt-bot`: скопируйте `.env.example` в `.env`, укажите `BOT_TOKEN`, установите Python 3.10+, Tesseract с `rus` и `eng`, затем выполните `pip install -r requirements.txt` и `python bot.py`. Тесты: `python -m unittest discover -s tests -q`.

## Подключение группы

Добавьте @svetovtestbot в группу и включите учёт командой `/enable` от администратора. В BotFather у бота должен быть выключен Privacy Mode, иначе обычные фотографии и текстовые сообщения группы не поступят. `/chatid` покажет ID группы. После новой квитанции или сообщения вида `Оплатил 800 ₽` либо `Имя: 800 ₽` бот сразу запишет платёж и напишет «Денег в казне: …». Кнопка «Отменить» удалит ошибочную запись. `/balance` показывает накопленный итог, `/month` — текущий месяц, `/month YYYY-MM` — выбранный месяц. Отчёт за месяц приходит первого числа после 00:05 по `Asia/Tomsk`.

## Старая история группы

Telegram Bot API не выдаёт боту сообщения, отправленные до его добавления. Для группы **«БРАТЬЯ СВЕТОВЫ»** выгрузите историю через Telegram Desktop: меню группы → **Export chat history**, формат **JSON**, включите **Photos**, выберите весь нужный период. Сохраните экспорт локально: `result.json` и папку с фотографиями. Не загружайте экспорт с перепиской и чеками в GitHub.

После добавления бота в группу и команды `/enable` получите её ID через `/chatid`. В каталоге `receipt-bot` выполните предварительную проверку:

```sh
python import_history.py '/путь/к/экспорту' --chat-id -1001234567890
```

Скрипт покажет количество найденных платежей, сумму до исключения дублей и ошибки OCR, не меняя базу. Сверьте сомнительные квитанции и затем добавьте `--apply` для записи. Локальная проверка не изменяет серверную базу. Для импорта на сервер скопируйте каталог экспорта в `data/receipt-bot/import/` и запустите из корня `reservation-service`:

```sh
docker-compose -f receipt-bot/compose.yaml exec -T bot python import_history.py /app/data/import --chat-id -1001234567890
docker-compose -f receipt-bot/compose.yaml exec -T bot python import_history.py /app/data/import --chat-id -1001234567890 --apply
```

Повторный импорт пропускает дубли по номеру квитанции или ID текстового сообщения. После импорта `/balance` покажет итог всей группы; `/month YYYY-MM` разнесёт платежи по дате квитанции или сообщения.

Импорт учитывает только распознанные банковские квитанции и строгие текстовые формы платежа. Обычные фотографии и разговоры не добавляются. Ошибки нужно проверить вручную: число найденных платежей не означает, что каждый перевод из переписки подтверждён.
